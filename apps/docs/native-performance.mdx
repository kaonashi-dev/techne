---
title: "Native performance"
description: "Measure the native app against the same routes in a hand-written fetch handler."
---

`createApp()` runs once at composition time and returns a Techne `App`. The app
compiles its routes, hooks and validators once, at `listen()` or on the first
request, and recompiles only after a route, hook or plugin is added. `createResources()`
runs at setup and shutdown only.

## Reproduce

From the repository root:

```sh
bun install --frozen-lockfile
bun run bench:native
bun run bench:native --quick
bun run bench:native --json
```

`benchmarks/native.ts` serves the same routes from a Techne native app and from a
hand-written `fetch` handler that does routing, validation and serialization by
hand (the floor). It exercises static JSON, path parameters with a service call,
validated JSON, and a native authorization hook. It verifies status and response
parity before timing, warms up both apps, alternates measurement order between
scenarios and reports throughput plus latency distributions.

These are in-process `Request`/`Response` measurements, not network capacity.
Run multiple full trials on the same machine for comparisons; short samples are
smoke checks, and small differences can be JIT/GC noise. There is no promised
speedup percentage. Socket throughput, cold import time and memory need their own
measurements with a representative application.

The older benchmark matrix measures the decorator runtime; those numbers are
not results for the new root API. Native correctness, plugin isolation and route
inference are checked with `bun test` and `bun run test:types`.
