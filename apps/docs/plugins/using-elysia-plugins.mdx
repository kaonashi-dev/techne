---
title: "Using Elysia plugins"
description: "Attach native Elysia plugins through app.use()."
---

Native Elysia plugins can be attached through `app.use()`:

```ts
import { myPlugin } from "some-elysia-2-plugin";

app.use(myPlugin());
```

Techne runs on Elysia 2, so the plugin itself must support Elysia 2. Plugins
written for Elysia 1.x fail even with the alias below. For example,
`@elysiajs/cors@1.4.x` calls `app.onRequest`, which Elysia 2 removed, and
mounting it throws `TypeError: app.onRequest is undefined`.

`app.use()` is the same path Techne plugins use under the hood after
`ctx.http()` resolves. Anything that works as an Elysia `.use()` argument
works here. For Techne-aware extension points (DI, lifecycle, named
dependencies), prefer [`definePlugin`](/plugins/plugin-protocol).

## Resolve `elysia` to Techne's copy

Techne bundles Elysia and TypeBox as source instead of depending on the
`elysia` and `typebox` packages. Plugins published to npm still
`import ... from "elysia"`, and an Elysia instance from a second copy cannot be
mounted: Elysia keeps its state in private class fields, so `.use()` throws
`Cannot access invalid private field`. Point those imports at Techne's copy in
`tsconfig.json`; Bun applies `paths` at runtime too, including to imports
inside `node_modules`:

```json tsconfig.json
{
  "compilerOptions": {
    "paths": {
      "elysia": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/index.ts"],
      "elysia/types": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/types.ts"],
      "elysia/error": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/error.ts"],
      "elysia/cookies": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/cookie/index.ts"],
      "elysia/type": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/type/exports.ts"],
      "elysia/trace": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/plugin/trace.ts"],
      "elysia/websocket": [
        "./node_modules/@kaonashi-dev/techne/src/vendor/elysia/plugin/websocket.ts"
      ],
      "elysia/ws": ["./node_modules/@kaonashi-dev/techne/src/vendor/elysia/ws/index.ts"],
      "elysia/auto-head": [
        "./node_modules/@kaonashi-dev/techne/src/vendor/elysia/plugin/auto-head.ts"
      ],
      "typebox": ["./node_modules/@kaonashi-dev/techne/src/vendor/typebox/index.ts"],
      "typebox/*": ["./node_modules/@kaonashi-dev/techne/src/vendor/typebox/*/index.ts"],
      "exact-mirror": ["./node_modules/@kaonashi-dev/techne/src/vendor/exact-mirror/index.ts"]
    }
  }
}
```

These are all the subpaths Techne exports. A plugin that imports another
upstream subpath (`elysia/ws/types`, `elysia/utils`, `elysia/context`,
`elysia/base`) has no Techne equivalent and still loads the npm copy, which can
break `instanceof` checks between the two copies.

These paths match the types Techne resolves when it is installed from GitHub
(source only). If the package also ships `dist/types`, TypeScript reads Techne's
Elysia from those declarations while the alias points at the source, and
`.use(plugin)` reports a `#private` mismatch even though it runs.
